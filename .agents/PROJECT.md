# EZ Binary Editor: project memory

Last updated: 2026-10-23.

## Purpose and user preferences

This is a DOS hex/binary editor rewritten from an abandoned assembly project.
The user's original blockers were memory corruption and stack resets. They
requested a readable, procedure-based `BINED3.ASM`, 486-class instructions,
command-line file loading, and hex/binary editing of modest-size files.

Persistent user requirements:

- Keep build, execution, and test instructions available in `README.md`.
- Provide a test option in `LAUNCH.BAT`.
- Preserve intermediate debugging sources for later reference, including
  sources stored under `BUILD`; do not blanket-clean that directory.
- Use green over black, dark-green secondary text, and purple highlights.
- Update this memory and the changelog after every changeset; root
  `AGENTS.md` makes that instruction discoverable for future agents.

## Architecture and invariants

- DOS real-mode EXE with a small-style layout: separate `USE16` code, data,
  and a 4 KiB stack. TASM 2.5 accepts `P486`, not `.486`.
- CPU instruction selection and memory model are separate. No DOS extender
  or flat/protected-mode addressing is used.
- `Main` owns the one editor event loop. Procedures return normally; there
  are no recursive renderer/input loops or production SP resets.
- Startup shrinks the PSP allocation through the end of the stack, then
  allocates up to 512 KiB using DOS AH=48h. On insufficient memory it requests
  the largest available block. Never write file data to arbitrary segments.
- File sizes/offsets are 32-bit. `MapBuffer` normalizes logical addresses into
  `FS:BX`. File transfers are at most 16 KiB and remap on every chunk.
- DS addresses DGROUP, apart from the bounded DOS-transfer window; file
  contents are kept in the separate DOS allocation.
- Bytes in memory are authoritative. Rendering/mode changes never parse
  characters back from video memory.
- Cursor may equal file size: EOF is an append position. Overwrite preserves
  other bits; newly appended bytes are zero-initialized. Insert/Delete shift
  bytes. Files exceeding actual buffer capacity are rejected.
- Saving writes/closes a unique sibling temporary file, renames the old
  target to a unique backup, then installs the new file. Failed installation
  attempts restoration. This is not power-loss-atomic. Successful replacement
  gives the file a new timestamp and normal attributes.
- Restore video mode/page and cursor settings on exit; prior screen contents
  are not retained. Free DOS memory and close all opened handles.

### Palette

The `ATTR_*` constants near the top of `BINED3.ASM` define VGA text attributes:

| Constant | Value | Meaning |
| --- | --- | --- |
| `ATTR_NORMAL` | `0Ah` | Bright-green data, ASCII preview, filename |
| `ATTR_TITLE` | `02h` | Dark-green title/dialogs |
| `ATTR_OFFSET` | `02h` | Dark-green offsets/headings |
| `ATTR_SELECTED` | `0Dh` | Purple selected byte and EOF marker |
| `ATTR_STATUS` | `0Ah` | Bright-green position/size/status |

All backgrounds are black. Existing video assertions check selected `A` as
`0D41h` and selected EOF `-` as `0D2Dh`.

## Build, execute, and test

Run commands from the project root on Windows/PowerShell:

```powershell
.\DOSBOX\DOSBox.exe -conf dosbox_bined.conf
```

Menu: **1** build/run, **2** build, **3** run existing, **4** build/test logs,
**5** DOS prompt, **6** build and run tests. Preserve option 5's meaning.

At the DOS prompt:

```dos
call BUILD.BAT
BUILD\BINED3.EXE TEXT.COM
call TESTS\TEST.BAT
```

With no filename the editor opens/creates `UNTITLED.BIN`; missing files start
empty. One quoted filename is accepted, subject to DOS-visible/8.3 paths.
F1 help, F2 save, F4 save-as, F5 binary, F6 hex, Tab mode, Esc quit.

Unattended build/test, followed by independent host verification:

```powershell
.\DOSBOX\DOSBox.exe -conf dosbox_bined.conf -noautoexec `
  -c 'mount c "."' -c 'c:' -c 'call BUILD.BAT' `
  -c 'call TESTS\TEST.BAT' -c 'exit'
python TESTS\VERIFY.PY
git diff --check
```

Prefer TASM output-directory syntax, e.g. `BINED3.ASM,BUILD\,BUILD\`.
Explicit existing `.OBJ` output paths produced a repeat-build path issue
with this bundled environment.

## Environment quirks and debugging references

- Bundled DOSBox 0.74-2 mounted drives accept read-only attribute changes but
  do not report them back. Tests explicitly report this and exercise directory
  protection instead; genuine read-only testing runs when DOS supports it.
- The core suite needs at least 131,089 bytes of file-buffer memory.
- `MENUKEY.ASM` installs a resident INT 16h feeder for keys 6, Space, 5. Run
  its launcher check in a fresh DOSBox session and exit that session afterward.
  Full reproduction commands are in its header and `README.md`.
- Redirected `MENU.IN` and Windows SendKeys did not reliably drive the menu.
  The earlier EXEC-to-COMMAND.COM attempt did not reliably complete the batch
  workflow. Use the working session-level `MENUKEY` feeder for automation.
- Do not remove debugging sources after verification: the user explicitly
  requested their restoration and preservation.
