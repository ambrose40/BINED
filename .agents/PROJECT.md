# EZ Binary Editor: project memory

Last updated: 2026-11-14.

## Purpose and user preferences

This is a DOS hex/binary editor with right-column ASCII and full-screen Text
editing, rewritten from an abandoned assembly project.
The user's original blockers were memory corruption and stack resets. They
requested a readable, procedure-based `BINED3.ASM`, 486-class instructions,
command-line file loading, and hex/binary editing of modest-size files.

Persistent user requirements:

- Keep build, execution, and test instructions available in `README.md`.
- Provide a test option in `LAUNCH.BAT`.
- Preserve intermediate debugging sources for later reference, including
  sources stored under `BUILD`; do not blanket-clean that directory.
- Use green over black, dark-green secondary text, and purple highlights.
- Main title is bright white; OFFSET/DATA/ASCII column labels are bright red.
  The active HEX/BIN/ASCII/Text label is bright yellow. Right-hand ASCII preview
  symbols are light gray, with the selected byte bright red during numeric
  HEX/BIN editing (including the dot for a non-printable byte); in ASCII
  editing the selected character/EOF marker is purple. Hex/binary selection
  remains purple in the data column.
  The filename and Save input are purple; the bottom status line and
  Save/unsaved-quit prompts are light gray.
- F1 help uses a centred, bordered modal text window with one instruction
  per line, bright-yellow key names, and light-gray descriptions/EOF note.
  The any-key return description stays dark green.
  Offset/Size/Capacity numeric values are dark purple.
- Update this memory and the changelog after every changeset, and review/update
  both before every commit with all completed work and actual verification.
  Root `AGENTS.md` makes both requirements discoverable for future agents.
- Use Conventional Commits messages (`type(scope): summary`) when committing.
- Current controls (2026-11-14 clarification): F5 selects BIN, F6 selects HEX,
  F7 selects full-screen Text. Tab toggles numeric/right-column ASCII focus in
  HEX/BIN, and inserts a tabulation byte in Text. This supersedes earlier
  Tab view cycling and F7 ASCII-focus behavior recorded in the changelog.
- Full-screen Text uses bright-green characters and a purple current character,
  matching HEX/BIN data. Enter inserts DOS CR/LF; Tab inserts `09h`, displayed
  using 8-column tab stops. The bottom-right corner shows HEX:/BIN: byte values.
- F8 opens Go to offset in every mode: absolute plain hexadecimal, 1..8 digits,
  Enter accepts, Backspace corrects, Esc cancels. Zero and EOF are valid; errors
  keep the dialog open without navigation/data changes.
- F9 opens search in every mode; Tab inside the dialog selects exact TEXT/HEX,
  Enter searches, empty Enter repeats, Backspace corrects and Esc cancels.
  F3 finds next and F4 finds previous. Patterns are case-sensitive ASCII or hex
  byte pairs, up to 32 bytes. Both search directions wrap once without edits.
- F2 is the universal Save/Save As action: it prefills the active path; Enter
  saves it, typing replaces the selected name, and arrows/Home/End enable
  in-place filename editing. Esc cancels. Only successful saves change the
  active filename/savepoint. The quit prompt's S uses this same dialog; cancel
  or failure returns to the editor. F4 is exclusively Find Previous.
- F11 undoes and F12 redoes up to 32 retained editing changes in RAM. CR/LF
  insertion/Text line joins are single changes; individual hex digits/binary
  bits are separate changes. No-ops/navigation do not consume history. New
  actual edits after undo discard redo; saves retain history and mark a clean
  history state. Undo/redo preserve the active mode/focus.

## Architecture and invariants

- DOS real-mode EXE with a small-style layout: separate `USE16` code, data,
  and a 4 KiB stack. TASM 2.5 accepts `P486`, not `.486`.
- CPU instruction selection and memory model are separate. No DOS extender
  or flat/protected-mode addressing is used.
- `Main` owns the one editor event loop. Procedures return normally; there
  are no recursive renderer/input loops or production SP resets.
  Its enhanced BIOS keyboard read (INT 16h/AH=10h) delivers F11/F12 scan codes
  85h/86h. Modal input loops still return to Main; the key feeder handles both
  standard and enhanced BIOS reads.
- Startup shrinks the PSP allocation through the end of the stack, then
  allocates up to 512 KiB using DOS AH=48h. On insufficient memory it requests
  the largest available block. Never write file data to arbitrary segments.
- File sizes/offsets are 32-bit. `MapBuffer` normalizes logical addresses into
  `FS:BX`. File transfers are at most 16 KiB and remap on every chunk.
- DS addresses DGROUP, apart from the bounded DOS-transfer window; file
  contents are kept in the separate DOS allocation.
- Bytes in memory are authoritative. Rendering/mode changes never parse
  characters back from video memory.
- `editMode`: 0 = HEX digit editing, 1 = BIN bit editing, 2 = right-column
  ASCII overwrite, 3 = full-screen Text insertion. Independent `viewMode` is
  0 = HEX, 1 = BIN, 2 = Text. F5/F6 select BIN/HEX numeric editing; F7 selects
  Text. Tab switches numeric/ASCII focus in HEX/BIN without changing layout
  or viewport; in Text it inserts `09h`. Mode/focus changes reset digitIndex
  and preserve file contents/cursorOffset, except Text normalizes an offset on
  the LF half of CR/LF to its CR cell. Numeric layout changes reset viewOffset;
  selecting the same numeric layout or toggling Tab focus preserves it. F7
  preserves an already-active Text viewport; entering Text from numeric resets
  its viewport and EnsureVisible scrolls to the cursor.
  HEX layout uses 16 bytes per row (320 per page),
  BIN uses 6 (120 per page), including when ASCII editing is active.
  `digitsPerByte` is 2/8/1 for navigation. Renderers use viewMode independently
  to retain two hex digits or eight binary bits while ASCII has editing focus.
- Text uses all 80 content columns across the existing 20 data rows (2..21),
  without numeric/offset gutters; title/header and status/path/footer remain.
  `NextTextRow` is the shared bounded parser for 80-column wraps, CR/LF,
  bare CR/LF, and tabs. `FindTextRow`, `TextColumn`, `TextOffsetAtColumn`, and
  `TextLineOffset` map byte offsets/display rows/columns without converting
  data. `EnsureTextVisible` tracks a row-aligned byte viewOffset and caches the
  hardware cursor's row/column. CR/LF and a tab expansion each have one cursor
  position; tabs use 8-column stops. Up/Down/PgUp/PgDn preserve the current
  column where possible, clamping to shorter rows; Home/End use display rows.
  Consecutive Up/Down/PgUp/PgDn remember textGoalColumn across short rows;
  non-vertical keys, edits and mode selection clear textGoalValid.
  Exact-width rows absorb an immediately following CR/LF, CR, or LF, so no
  phantom blank row is created. `textRowWidth`/`textRowKind` expose the parsed
  row's boundary. Full-row End stays on its last byte, including at EOF.
  A selected full-width newline uses a purple `<` in column 79; its raw offset
  and inspector value still refer to the newline. Cursor columns stay 0..79.
  A bounded 128-entry offset/absolute-row ring caches each 32nd scanned row and
  recent lookup rows. FindTextRow/TextLineOffset start from the nearest valid
  checkpoint. WriteByte marks the earliest modified offset; DeleteByte marks
  even a tail deletion; LoadFile resets the cache. Lazy validation drops anchors
  from two bytes before an edit onward (CR/LF boundary effects), keeping earlier
  prefixes. Unmarked size changes reset the cache conservatively. DGROUP array
  indexing must use 16-bit SI/DI/BP with DS overrides for BP: TLINK 4 rejects
  32-bit relocation records emitted by symbol-plus-ESI/ECX addressing.
- `EditText` inserts printable characters and tabs rather than overwriting;
  Enter inserts `0Dh 0Ah` only if both bytes fit. `InsertTextCharacter` reuses
  DOS-owned byte storage/shifting. Backspace deletes the preceding character;
  `DeleteText` removes a CR/LF pair together to join lines. Insert retains zero-
  byte insertion. Other unassigned controls/high-byte input are ignored. All
  existing bytes are preserved by rendering/mode changes; non-printables are
  dots, selected newlines are purple blanks, EOF is `-`.
- `HandleKey` wraps `DispatchKey` in BeginHistoryChange/EndHistoryChange, recording
  actual file mutations as one editing-key transaction (including multi-byte
  CR/LF operations). Navigation, dialogs, undo/redo and no-ops are excluded.
  Root UNDO.INC owns 32 fixed 32-byte records plus a pending record (~1.1 KiB),
  with 32-bit offset/size/cursor/revision IDs, old/new 0..2-byte spans and digit
  positions. Current editing commands affect at most two bytes; full-file or
  video snapshots are never stored. Appending a real edit truncates redo and
  evicts the oldest record when full. Replay validates size/range/capacity
  before mutation, replays overwrites in place, and reuses InsertByte/DeleteByte
  for length changes under a replay guard. Cursor/digit selection is restored
  compatibly with the current mode, then EnsureVisible normalizes/scrolls it.
  MarkTextChanged still invalidates Text/search state during replay.
- History revision IDs distinguish saved/unsaved branches. HistoryMarkSaved is
  called only on successful SaveDocument completion; undo/redo to that saved
  state clears dirty. Failed saves leave the saved marker unchanged; saving an
  undone state retains redo. Identical manual content edits remain new states.
  LoadFile resets history and marks successfully loaded data clean. Low-level
  WriteByte calls outside an editing transaction/replay reset history (fixtures
  and future external buffer changes cannot leave stale records). Direct
  primitive calls are not user-history transactions; interactive HandleKey is.
- `RenderTextValues` writes the bottom-right `HEX: XX  BIN: XXXXXXXX` field at
  zero-based row 24, columns 58..79: green labels/dark-purple values. It reads
  the selected byte directly; at EOF it can show `textLastByte` after successful
  typing (`0Dh` for Enter), until another key clears `textLastValid`. With no
  selected/typed byte it shows dashes. `RenderText` uses bright-green text and
  purple selection; a selected tab highlights only its first expansion cell.
  Text row 22 columns 54..76 additionally show one-based hexadecimal Ln/Col
  and a yellow INS indicator. The Text footer is explicitly bounded to 58
  columns so it cannot overwrite the byte inspector. Interactive save errors
  open a 78x14 bordered modal at (1,5), with full message, lastError (hex),
  target/original or backup path and any retained staging path. Paths wrap
  within two 74-column rows. SaveDocument preserves the original install error
  across successful rollback and clears stageExists after successful cleanup.
- ASCII mode uses the right-hand column (zero-based 61 in HEX, 66 in BIN) for
  its cursor and purple character/EOF selection. The yellow title says
  `ASCII (HEX)` or `ASCII (BIN)`. `EditAscii` overwrites/appends a complete
  printable 7-bit byte (`20h`..`7Eh`) and advances one byte. Space types `20h`
  in ASCII; it still navigates in HEX/BIN. Backspace navigates without deletion.
  Unassigned controls (including Enter), DEL, and extended characters are
  ignored; edit non-printable bytes with HEX/BIN. Existing non-printable bytes
  display as dots. Identical overwrites preserve the dirty flag. Full-buffer
  EOF input reports `msgFull`, but existing bytes can still be overwritten.
- Cursor may equal file size: EOF is an append position. Overwrite preserves
  other bits; newly appended bytes are zero-initialized. Insert/Delete shift
  bytes. Files exceeding actual buffer capacity are rejected.
- `GotoDialog` is a balanced local BIOS input loop using rows 23/24, with gray
  prompt/errors, purple input, green current/EOF labels and dark-purple values.
  `ResetGotoInput`, `HandleGotoKey` and `RenderGotoDialog` separate input state
  from navigation. A nine-character bounded field makes overlength input
  visibly invalid; `ParseHexOffset` accepts only 1..8 hex digits, accumulates
  in EDX and returns full 32-bit EAX/CF without overflow or AL corruption.
  `ApplyGotoOffset` rejects offsets >fileSize instead of clamping, then resets
  digitIndex/preferred-column/typed-byte fallback and calls EnsureVisible.
  All modes/foci are preserved; Text retains its established LF-to-CR cursor
  normalization. Esc, bad input and range errors retain cursor/view/digit state.
- Saving writes/closes a unique sibling temporary file, renames the old
  target to a unique backup, then installs the new file. Failed installation
  attempts restoration. This is not power-loss-atomic. Successful replacement
  gives the file a new timestamp and normal attributes.
- F2/quit-save call SaveDialog, which separates ResetSaveInput, HandleSaveKey,
  RenderSaveDialog and ApplySavePath. inputPath is prefilled and initially
  replace-on-type; Backspace/Delete clear that selection, navigation clears
  selection for ordinary insertion/deletion at saveInputCursor. saveInputView
  keeps a 78-cell field/caret in bounds. Input is limited to 127 chars; an
  attempted overflow blocks saving until corrected, and empty names stay in
  the dialog. ApplySavePath uses staged SaveDocument then copies the new name
  only after success. saveInputDone: 0 editing, 1 saved, 2 cancelled, 3 DOS
  failure. SaveDialog shows the existing error modal on failure and returns CF
  set for failure/cancel, so QuitDialog cannot exit without a successful save.
  Input/navigation do not consume undo history; successful saves retain redo
  and update only the saved history marker. Choosing a new path retains the
  old file, as Save As did.
- Search uses separate F9 draft/candidate/committed pattern buffers, so invalid
  input and Esc never replace the previous pattern. `ResetSearchInput` defaults
  to HEX in numeric focus and TEXT in ASCII/Text, then remembers accepted type.
  `HandleSearchKey` keeps input bounded (96 visible chars + terminator); parser
  accepts at most 95 raw chars and 32 decoded bytes. Text is exact printable
  ASCII; HEX permits spaces between complete pairs, including zero/high bytes.
  `BuildSearchPrefix`/`SearchSegment` implement KMP using a 32-word prefix table
  and DOS-owned ReadByte access. `FindSearchPattern` scans from a candidate
  offset to EOF and earlier candidates once, allowing overlapping matches and
  matches across the starting position/64 KiB but never across physical EOF.
  `RunSearch` navigates only on success and preserves editing mode/focus/data/
  dirty state; a miss changes only search history/status. New queries start at
  cursorOffset; RepeatSearch (F3 or empty Enter) starts after the current match.
  RepeatPreviousSearch (F4) starts before its raw match anchor. Shared
  SearchSegment supports first/last match selection and resets KMP state to a
  proper prefix after a remembered match, preserving overlaps. Backward search
  finds the final matching candidate in the bounded prefix, then the suffix
  on wrap; each range remains linear and never crosses physical EOF. Direction
  switching preserves the pattern, mode/focus, dirty state and undo history.
  Raw `searchLastMatch` and normalized `searchCursorAtMatch` keep LF searches
  progressing in Text mode. Byte writes/deletions and loads invalidate that
  match anchor. RenderSearchDialog uses rows 23/24, gray prompt/errors, purple
  input (last 48 chars), green Mode label and yellow TEXT/HEX type.
- Restore video mode/page and cursor settings on exit; prior screen contents
  are not retained. Free DOS memory and close all opened handles.

### F1 help window

`HelpDialog` hides the hardware editing cursor, calls `RenderHelpWindow`,
consumes one BIOS key, restores the cursor shape, and returns to Main for
the normal editor redraw. It does not modify file contents or navigation.
`RenderHelpWindow` clears only a centred 58-column by 21-row rectangle at
column 11, row 2 (zero-based), then draws a purple CP437 border/title,
17 instruction lines with yellow key names and light-gray descriptions,
and an any-key return prompt with a yellow key label/dark-green description.
The `helpLines` pointer table places one instruction/sentence on each row.
`PutHelpLine` draws each string in its description colour, then highlights
the key label before the colon using `ATTR_HELP_KEY`; sentences without a
colon stay light gray. The EOF append explanation is now in the ASCII/Text
description; F11/F12 use its former standalone row without enlarging the modal.
The digit-input line uses a colon-delimited key label too.

## Build, execute, and test

Run commands from the project root on Windows/PowerShell:

```powershell
.\DOSBOX\DOSBox.exe -conf dosbox_bined.conf
```

Menu: **1** build/run, **2** build, **3** run existing, **4** build/test logs,
**5** DOS prompt, **6** build and run tests. Preserve option 5's meaning.

At the DOS prompt:

```dos
call BUILD.BAT
BUILD\BINED3.EXE TEXT.COM
call TESTS\TEST.BAT
```

With no filename the editor opens/creates `UNTITLED.BIN`; missing files start
empty. One quoted filename is accepted, subject to DOS-visible/8.3 paths.
F1 help, F2 universal save (prefilled editable path), F5 binary, F6 hex, F7 Text; Tab toggles numeric/
right-column ASCII in HEX/BIN or inserts a tab byte in Text. F8 goes to an
absolute hexadecimal offset. Esc quits.
F9 searches text/hex; F3/F4 find next/previous with wrap-around.
F11 undoes and F12 redoes the last retained edit (32 changes total in memory).

Unattended build/test, followed by independent host verification:

```powershell
python TESTS\RUN.PY
python TESTS\HOSTTEST.PY
python TESTS\VERIFY.PY --fresh
git diff --check -- AGENTS.md BINED3.ASM README.md TESTS .agents
```

Use `Start-Process -Wait`: a direct GUI EXE invocation can return before DOSBox
finishes, causing host verification to read stale/incomplete output. The full
`git diff --check` reports native DOS-generated whitespace in tracked LST/MAP/
log files; preserve these artifacts and check authored source/docs separately.
The preferred RUN.PY command handles waiting, removes only named workflow
products, gates BUILD/TEST via TESTS/ALL.BAT, checks completion markers and
linker logs, and records source/output hashes in local ignored VERIFIED.JSON.
Plain VERIFY checks existing artifacts; --fresh additionally requires matching
provenance. BUILD.OK/TEST.OK and Python cache files are ignored, not committed.
The source manifest includes root UNDO.INC as well as test includes; HOSTTEST
also checks that changing the undo source invalidates a fresh result.
TEST.BAT requires a successful BUILD.BAT in the same DOS session.

Prefer TASM output-directory syntax, e.g. `BINED3.ASM,BUILD\,BUILD\`.
Explicit existing `.OBJ` output paths produced a repeat-build path issue
with this bundled environment.
